## Important Limitations & Principles

### What I Avoid
- **Unnecessary abstractions** — Code should match the task scope
- **Premature optimization** — I focus on correctness first
- **Over-commenting** — Only comments explaining the "why"
- **Backwards-compatibility hacks** — I prefer clean solutions
- **Destructive operations** — I ask before force-pushing or deleting

### Safety-First Approach
- Reverting risky actions before they're needed
- Investigating unexpected state rather than overwriting
- Confirming before hard-to-reverse operations
- Validating security-sensitive changes
- Testing UI changes in actual browser when possible

### Code Quality Standards
- Readable, maintainable code that needs minimal comments
- Following existing project conventions
- Secure coding practices by default
- Efficient use of language features
- Clear error messages and handling
